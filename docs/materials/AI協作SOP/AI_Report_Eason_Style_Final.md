# 台灣大哥大 網站技術課- AI 導入成效與治理報告

**網站技術課 課長 Eason Tsai**

## 一、 核心定義：Eason-Style 與 TAI-Builder 協作矩陣

這兩者相輔相成，前者是「開發者與 AI 互動的核心工法與心態」，後者則是「組織層面的開發流程標準化與效率框架」。

### 1. Eason-Style (核心工法與心態) ——「靈魂」
由技術課長 Eason 所提倡的 AI 協作工法，其核心思維是：**「開發不是單次性的生成，而是具備時間維度、邊界清晰且全面掌控的持續疊代過程。」**

* **控制權高於生產力 (Control over Productivity)**
  * 使用 AI 不是盲目讓它寫代碼，而是透過嚴格規範（如在 `TAI-BUILDER` 下使用 `CLAUDE.md`）來掌控邊界與品質，消除 AI 的幻覺。
* **基於 Harness Engineering 的精神**
  * 提倡 **Spec-first (規格先行)**，利用 OpenSpec 等工具先定義技術協議，再讓 AI 執行，確保代碼產出符合企業級標準。
* **藍圖反饋機制 (System Blueprint)**
  * 強調系統狀態的連續性。在每個 Use Case (UC) 完成後即時更新系統藍圖，解決系統疊代時脈絡遺失的痛點，讓 AI 具備長期記憶。

#### ▍方法本質差異對比
| 面向 | 一般 AI 開發 | Eason-Style AI 協作 |
| :--- | :--- | :--- |
| **核心單位** | Prompt | **UC (Use Case)** |
| **AI 角色** | 工具 (Tool) | **開發節點 (Agent Node)** |
| **控制方式** | 人工即時修正 | **結構化約束 (Skill + 規範)** |
| **輸出型態** | 不穩定 (每次不同) | **可預期 (標準化輸出)** |
| **知識來源** | 單次輸入 | **Context + 規範 + 歷史** |
| **可重用性** | 低 | **高 (Skill 化)** |

#### ▍對應 Harness Engineering 架構
| Harness 元件 | 一般 AI | Eason-Style |
| :--- | :--- | :--- |
| **Constraints (約束)** | 幾乎沒有 | **CLAUDE.md / 規範** |
| **Tools (工具)** | 無明確分層 | **Web / API / Backend Skill** |
| **Context (上下文)** | 單次 prompt | **UC + 架構 + 文件** |
| **Memory (一致性)** | 幾乎沒有 | **UC 編號 / 命名規則** |
| **Feedback Loop (回饋)** | 人工修 prompt | **propose $\rightarrow$ review $\rightarrow$ apply** |

---

### 2. TAI-Builder AI 協作矩陣 (組織效率框架) ——「骨架」
這是將 Eason-Style 的工法落實到軟體開發生命週期 (SDLC) 中的組織級框架。依據任務規模區分為「大、中、小、管」四大格局：

* **大格局 (Macro Level)**：架構設計與決策加速。
* **中格局 (Meso Level)**：SA 與 API 工程標準化。
* **小格局 (Micro Level)**：PG 實作與 5x-8x 效能開發。
* **管理層 (Management Level)**：治理標準與人才發展。

## 三、 公司治理與風險管控 (Governance)

為確保 AI 導入不產生技術債，課內導入以下監測指標：

> * **用量監測**：追蹤任務互動回合數與 **Lead Time**（開工到合併時間）。
> * **品質防禦**：建立 `ai-spec-drift`（規格偏移）標籤系統，監控 CI Fail 率。
> * **瓶頸移轉分析**：數據顯示編碼僅需 2-6 分鐘，但 Review 佔比高達 60%，突顯資深審查者的重要性。

## 四、 觀點總結

* **方法論大於工具**：團隊是在經營「協作體系 (TAI-Builder)」，而非單純使用工具。
* **資產化 Prompt**：將開發邏輯資產化為 `.md` 文件，是技術課的核心無形資產。
* **從「扛錯」到「掌控」**：使用 AI 的目的在於全面掌控品質與進度。
* **協議驅動開發**：透過 AI 生成 API 協議，前端與後端開發精準對接，大幅減少溝通成本。
* **數位勞動力轉型**：由 AI 承擔重複性工作，使工程師專注於 20% 的核心商業邏輯。
* **人才培養加速**：AI 輔助 Code Review，顯著縮短 Junior 工程師的上手時間。
